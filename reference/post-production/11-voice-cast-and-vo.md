# Voice Cast and Voice-Over

Voice belongs to a **character**, not to a video. One scene can carry a supporting character speaking
on screen followed by the narrator speaking over the same shot, in two different voices, and both have
to stay the same across every scene they appear in.

Read with `10-post-production-pipeline.md` (folder contract, `audio-plan.json` schema) and
`global-promo-config.md` §29.4 (the values).

---

## 1. The `VOICE:` block

One per cast member who speaks. Lives in `cast-profile.md`, written by the Phase 1 cast builder or
added in Phase 5 when a character turns out to have a line.

```markdown
VOICE:
  provider: elevenlabs
  voice_env: ELEVENLABS_VOICE_C1        # env var NAME holding the voice id — never the id itself
  model: eleven_multilingual_v2         # never v3
  settings: stability=0.55, similarity_boost=0.8, style=0.3, speed=0.95
  source: tts | native+changer
  description: "<10-15 words, verbatim in every platform prompt for this character>"
```

| Field | Meaning |
|---|---|
| `provider` | `elevenlabs` today. The field exists so a second provider does not require a schema change. |
| `voice_env` | The NAME of the environment variable holding the voice id. `ELEVENLABS_VOICE_C{N}` per cast slot, `ELEVENLABS_VOICE_NARRATOR` for the narrator. |
| `model` | `eleven_multilingual_v2`. **Never v3** — it has no PVC fine-tune, so it reconstructs from raw samples and the identity drifts between requests. |
| `settings` | Locked recipe. Change it and the same character sounds different between videos. |
| `source` | `tts` = this character's speech is generated by ElevenLabs. `native+changer` = the video platform speaks the line so the lips match, then `voice_changer.mjs` converts it into this voice. |
| `description` | The 10-15 word voice description, copy-pasted verbatim into every platform prompt for this character. Paraphrasing it is what makes a voice drift between scenes. |

**Why the id is not in the repo.** This plugin is client-agnostic by contract — the project CLAUDE.md
forbids hardcoding project-specific values. A voice id identifies one person's cloned voice on one
account. It lives in the user's `.env`, and the repo only ever names the variable.

Missing variable? The tool stops with `voice env ELEVENLABS_VOICE_C2 not set`, prints the manual
command, and the skill continues with what it can still do. It never picks a substitute voice.

## 2. Choosing the source per character

```
Does this character ever speak ON SCREEN with the face over 30% of frame?
├── YES → source: native+changer
│         The platform speaks the line so the mouth matches. The voice is
│         normalised afterwards. Losing lip-sync is worse than a voice that
│         needs one conversion pass.
└── NO  → source: tts
          Narration, over-the-shoulder, back-of-head, mouth out of frame.
          ElevenLabs speaks it directly, and nothing has to sync.
```

The usual shape of a promo: the narrator is `tts`, an on-screen presenter is `native+changer`, and a
walk-on character with one line is `native+changer` too.

## 3. VO-first: the audio sets the duration

When the audio source is `elevenlabs` or `mixed`, narration is generated BEFORE prompts are written.

```
av-script.md narration
   └── tools/gen_vo.mjs
         ├── vo/scene-{NN}-narr.mp3
         └── vo-manifest.json   ← measured duration + word timings
                └── scene duration in scene-plan.md
                      └── clip length asked of the platform
```

A word count is a guess; the mp3 is a measurement. Kling takes an exact second between 3 and 15, VEO
generates 8s and extends, Seedance goes to 15s — all three can be given the right number the first
time instead of after a re-generation.

The word timings in `vo-manifest.json` are also what the subtitle pass reads, so captions cost no
extra transcription when the narration came from ElevenLabs.

---

## 4. Prosody across scenes

Consecutive requests are stitched with `previous_request_ids` so the delivery carries across scene
boundaries. Without it each scene is spoken cold and the video sounds like a series of separate
recordings read by the same person.

Order matters: generate in **script order**, not in whatever order the scenes were approved.

---

## 5. Voice Changer (speech-to-speech)

For a character whose `source` is `native+changer`:

```
clip audio  →  ffmpeg extract  →  ElevenLabs speech-to-speech  →  vo/scene-{NN}-c{N}.mp3
                                          ↓
                              duration must be preserved
```

**The 0.05s rule.** Speech-to-speech keeps timing and rhythm, which is exactly why lip-sync survives
the swap. That is a property to VERIFY, not to assume: if the converted audio differs from the source
by more than 0.05s, the tool refuses to write it and reports the drift. See §29.4
`voice_changer_max_drift_s`.

If drift is real and persistent, the mixed-source strategy itself is wrong and has to be reopened —
not worked around with a stretch filter, which introduces artefacts in the voice this whole system
exists to keep consistent.

## 6. Prompt-level discipline

These apply to every platform prompt, in every phase, and they are the cheap half of voice
consistency:

- **Verbatim voice description.** Copy the `description` field character for character. A paraphrase
  is a different voice to the model.
- **One emotion per scene.** "Calm, then excited" inside a single clip produces neither.
- **Accent stays locked** across all scenes for a character. Name it once, repeat it verbatim.
- **No em dash in spoken text.** `—` is mistranslated by the audio engine. Use `,` or `. `. This
  applies to narration and dialogue, not to burned captions, which are printed rather than read
  aloud.
- **Generic role, never a real name.** `Host says:` / `Presenter says:`. A real person's name plus a
  photoreal face trips the prominent-people safety filter.

---

## 7. What each mode costs

| Mode | Regeneration cost of a script edit | Voice consistency | Lip-sync |
|---|---|---|---|
| `platform-native` | re-generate the clip (expensive) | drifts between clips | automatic |
| `elevenlabs` | re-generate the mp3 (cheap) | exact | not possible on screen |
| `mixed` | mp3 for narration, clip only for the scenes that show a mouth | exact after conversion | preserved |

`mixed` is the usual answer for a promo with a presenter, and it exists because the two failure modes
are not symmetric: a drifting voice is noticeable across a whole video, while a re-generated clip
costs credits once.
